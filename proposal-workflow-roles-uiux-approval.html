Part B — Target operating model

2. Target weekly process (beginning → end)

One reporting week (Monday–Friday). Global Week selects the operating week. Home is the control tower until Week Close is complete.

01 PrepareOwners submit
02 ValidateQuality check
03 ReviewMeeting
04 DecideGates
05 CommunicateFeedback
06 Follow-upActions

Stage-by-stage specification

StageInputWorkExit criteria (done when…)Primary screen
01 Prepare Assigned products / workstreams for the week Owners create or update weekly reports with role-correct fields, summary, next action, health All expected owners have a report for Global Week (or explicit “no update” waiver) Weekly Updates / Intake
02 Validate Submitted reports Quality review: missing summary/next, weak evidence, bad dates; fix or waive with reason Quality gaps = 0 or all remaining gaps waived Report Quality Review
03 Review Validated portfolio for the week Manager meeting session: agenda → health scan → capture decisions Agenda items reviewed; open risks acknowledged Management Review (session)
04 Decide Gate-ready items + evidence packs Approvals / conditions / rejects with rationale; block Approve if role-minimum evidence missing No Critical open decisions without owner + due — or explicitly deferred Product Governance
05 Communicate Meeting outcomes + owner metrics Send weekly feedback (or defer with reason); record send history Feedback sent to selected owners OR deferred logged Weekly Review
06 Follow-up Decisions and next actions Every action has owner + due + status; track until closed All new actions assigned; overdue visible on Home Action Items

Week Close checklist (definition of done)

Home shows this checklist for the selected Global Week. Week is Closed only when all five are true (or waived with reason).

#CheckPass rule
1Reports submittedExpected owners in scope have updates for the week
2Quality clearOpen quality gaps = 0 or waived
3Critical decisions closedNo Critical gate/decision without resolution or deferral
4Actions assignedNew actions have owner + due date
5Feedback handledSent OR deferred with reason recorded

3. Roles model (must approve separately from UI)

3.1 Two layers — do not mix

Access profile Who can use which system capabilities (view / create / edit / administer).
  • Portfolio Viewer
  • Reporting Editor
  • Operations & Access Manager
Functional responsibility What delivery work a person owns on a report or governance item.
  • Product Manager
  • UI/UX
  • Training

3.2 Access capability matrix

Access profileCan doCannot doTypical functional role
Portfolio Viewer View Home, Portfolio, Executive, Incidents, Timeline, Governance (read) Create/edit reports; administer users Leadership / stakeholders (C/I)
Reporting Editor Create/edit weekly updates, timeline, governance items; My Dashboard User admin; weekly feedback blast; full quality ops PM / UI/UX / Training owners (A for own work)
Ops & Access Manager All editor rights + quality review, meeting run, users, feedback send, logs — Process owner for Week Close (A for cadence)
Copy cleanup required: remove remaining “Master admin” / “Role Manager” strings from alerts and journey labels. Public labels above become the only vocabulary.
