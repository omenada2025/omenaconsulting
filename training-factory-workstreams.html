2. Multiple versions — how we do not lose tracking

A product can have a live version (Support PM) and a next factory cycle (Live PM) at the same time. Accept moves the “live pointer”; it does not erase history.

Checkout Hub (product — stable name) ├── v1.1 · Live ops ← Support PM · weekly status + kits ├── v1.2 · Factory W3 ← Live PM · runway + gates (parallel) └── v1.0 · Closed ← history · do not mix into this week’s update
Product Stable identity in the portfolio (name does not change each release).
Version / cycle One 6-week runway + one handover. Own V0 date, kits, and gates.
Live pointer After Accept, Support PM owns that version as Live ops. Previous live → Closed / history.

Rules (everyone)

  • Do not mix live bugs and factory gate work in the same weekly update line.
  • Kits (Launch / Run / Live Product) are per version.
  • Use a clear label: e.g. Checkout Hub · v1.2 or a Version / cycle field when it ships.
  • Empty V0 date = that version is not on the factory runway (weekly status still works).
One-liner for the team: Support PM owns the current live version. Live PM owns the next factory cycle. Tracking is per version; Accept moves the live pointer.

Support PM

5. Support PM workflow (final)

A. Current live version (you own it)

  • Role = Support PM · stage = Live ops.
  • Weekly: status, risks, support load, training/demos, sustaining.
  • Keep kits current for this live version when something material changes.

B. Next factory version (Live PM still owns)

  • Do not take ownership early.
  • Week 5: enablement / reverse demo rehearsal.
  • Week 6: review kits + QA + access for that version.
  • Accept: only Support PM. Incomplete kits → hold; Live PM closes gaps.

C. After Accept

  • Live pointer moves to the new version → you own Live ops.
  • Previous live version → Closed / history (still findable, not mixed into weekly live).
  • Live PM moves to the next factory product or cycle.
Locked: Accept handover = Support PM only.
Live PM

6. Live PM (Builder) workflow (final)

  1. Receive formal V0 / pack → set V0 received date on that version/cycle.
  2. Run Weeks 1–6; gate evidence at weeks 1, 3, 5, 6.
  3. Build Launch / Run / Live Product kits for this version before Week 6.
  4. Coordinate Support PM reverse demo (Week 5–6).
  5. Wait for Support PM Accept → then start the next product or version cycle.

If Support PM already owns v1.1 live, your v1.2 factory stream runs in parallel — do not overwrite their live tracking.

FAQ

9. FAQ

Do weekly updates stop during the 6 weeks?

No. Weekly rhythm continues. Factory is an extra layer on the version in delivery.

Can live and next version run in parallel?

Yes. Support PM on live version; Live PM on next factory cycle. Separate tracking lines.

Can Ops Manager accept handover?

No. Support PM only.

What about old products?

Manual. Migrate when ownership is clear.

When does build start?

After this training is shared, feedback collected, and leadership confirms A1–A5.
